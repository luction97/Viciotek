# Decisiones vigentes

1. **WPF/.NET 8**: escritorio Windows nativo, sin Electron ni servidor. No migrar plataforma durante correcciones. Revisar actualización de LTS antes de finalizar soporte de .NET 8.
2. **Capas en un único ensamblado**: separación por carpetas suficiente para este alcance; no crear proyectos/interfaces sin necesidad.
3. **Sin dependencias de ejecución externas**: Shell COM/PInvoke, WPF imaging y `System.Text.Json`; xUnit solo para tests.
4. **Portadas primero**: tarjetas fijas de 200×300 DIP, columnas según ancho y separación de 16 DIP; sin textos permanentes debajo, sidebar ni estadísticas.
5. **Virtualización propia**: `VirtualizingWrapPanel` limita contenedores al viewport ampliado. El código elimina/recrea contenedores, no implementa reciclaje explícito; no afirmar lo contrario.
6. **Miniaturas locales 2:3**: original copiado y JPEG 480×720 con recorte central; UI `UniformToFill`. Decodificación a 320 px, LRU acotada de 32, sin retener archivos abiertos.
7. **Lanzamiento restringido, no sandbox**: `.lnk` resuelto conserva argumentos/directorio; destino `.exe/.com`; `.url` solo protocolos conocidos. El usuario debe confiar en los ejecutables. Windows puede aceptar un proceso que luego falle.
8. **JSON local**: esquema 1, guardado atómico y `.bak`; sin base de datos ni sincronización remota. Desde 1.0.1 se impiden escritores simultáneos por directorio con un handle de archivo, sin servicio residente.
9. **Red opcional**: SteamGridDB solo tras importación o solicitud manual y con clave. Nunca buscar portadas al iniciar. Error de red no impide usar la biblioteca.
10. **Mediciones honestas**: separar HWND, primer frame, arranque frío/caliente y memoria privada/working set. El objetivo de RAM ≤100 MB no está cumplido en el entorno disponible.
11. **Revisión de portada sin migración** (2026-10-27): reutilizar `CoverFileName` como versión para el binding y la LRU. Evita píxeles obsoletos al reemplazar la miniatura de ruta estable sin cambiar el esquema JSON ni invalidar imágenes de otras tarjetas.
12. **Interfaz sin instrucciones obvias** (2026-10-28, solicitud del usuario): retirar indicaciones de doble clic, tutorial de bienvenida y confirmaciones redundantes; conservar lanzamiento por doble clic/Enter, personalización local y mensajes de error útiles. Nombre solo en hover/foco; configuración desde la marca, automatismos opcionales fuera de vista hasta configurarse.
13. **Trabajo de imágenes acotado** (2026-10-28): dos decodificaciones simultáneas, agrupación de bindings y una fila de margen por lado. El worker Shell se crea de forma diferida. No afirmar menor RAM sin medir: la comparación disponible no demuestra reducción significativa.
14. **Portadas transaccionales y miniatura por revisión** (2026-10-28): preparar sin borrar, guardar el JSON y adoptar después; descartar el par nuevo ante fallo. La miniatura se identifica por el nombre del original (con lectura legada por `gameId`), lo que permite regenerar el caché sin duplicar estado en el JSON.
15. **Cierre que drena operaciones** (2026-10-28): el cierre cancela el token de vida, descarta el toast y espera las operaciones en curso antes de liberar recursos; las mutaciones abortan/revierte su trabajo parcial. No forzar `Dispose` durante trabajo activo.
16. **Accesos reconocibles sin botones permanentes** (2026-10-28): engranaje para Preferencias y lápiz de portada solo en hover/foco. Enter en búsqueda lanza el resultado visible; no son textos tutoriales, son convenciones visuales.
17. **Medición de interfaz opt-in** (2026-10-28): `StartupProbe` con variables de entorno mide hasta "covers listas" (fotograma WPF, no GPU) y pasos de scroll; sin timers, archivos ni trabajo extra en uso normal.
18. **Identidad visible VICIOTEK** (2026-10-28): identidad visible `VICIOTEK`, ejecutable `Viciotek.exe`, autoría `Lucas Siano` en Acerca de y metadatos. Primera etapa del rebranding; el renombre interno completo se hizo en 1.1.0 (decisión 25). La autoría es discreta y opcional de consultar.
19. **Ventana maximizada dentro del área de trabajo y animación opcional** (2026-10-28): se clampa `WM_GETMINMAXINFO` para que el contenido inferior (toast) no quede detrás de la barra de tareas. El hover de portadas es un efecto visual desactivable (`AnimationsEnabled`, activo por defecto), sin estados nuevos ni complejidad en el view model.
20. **SteamGridDB real, seguro y persistente** (2026-10-28): cliente HTTP real con búsqueda, galería de portadas y verificación de conexión. La clave se protege con DPAPI (sin dependencias NuGet) y se migra desde texto plano. La galería descarga miniaturas con concurrencia acotada y guarda solo la portada confirmada. Sin red al iniciar salvo auto-fetch activo en importación. Las imágenes de SteamGridDB pueden tener restricciones de redistribución comercial; revisar antes de publicar VICIOTEK.
21. **Identidad local y selección conservadora** (2026-10-28): fuentes locales ordenadas y limitadas, Steam AppID antes de texto, hasta tres consultas textuales distintas. No expandir siglas ni confundir secuelas/ediciones; nunca aceptar el primer resultado por posición. Persistir asociación y consulta por separado del nombre visible. Sin coincidencia fiable, galería secuencial con campo manual vacío; cancelación y errores HTTP no alteran juegos ni portadas. Usar `thumb` para navegar y descargar el original únicamente al elegirlo. No agregar servicios ni dependencias.
22. **Contrato HTTP real y versión distinguible** (2026-10-28, 1.0.3): centralizar dimensiones oficialmente admitidas después de reproducir HTTP 400 con 300×450. Probar parámetros reales, no solo respuestas simuladas permisivas. Verificar la clave escrita antes de Guardar y mostrar actividad de portada sin bloquear la biblioteca. Publicar 1.0.3 por separado: no sobrescribir ni cerrar el 1.0.2 en uso. La herramienta de prueba admite red únicamente con `--live` y clave de entorno; no distribuye credenciales.
23. **Instalador por usuario sin datos en juego** (2026-10-28, 1.0.4): Inno Setup, `{localappdata}\Programs\VICIOTEK`, sin elevación, acceso directo de escritorio incondicional, y ninguna regla que borre datos personales o archivos desconocidos en instalar/desinstalar/actualizar. Setup no cierra procesos por la fuerza: un mutex de presencia (`AppMutex`) bloquea la instalación mientras la aplicación está abierta, verificado por smoke. Sin firma digital todavía: SHA256 como integridad, no como autoría. La compilación de pruebas redirige accesos y no registra desinstalación; el instalador de distribución no lleva esos valores.
24. **Repositorio auditable y reproducible** (2026-10-28): baseline escaneado con Gitleaks antes del primer commit; ramas breves y Conventional Commits con hooks opcionales y verificación en CI; SDK/paquetes fijados con lock files y NuGetAudit como error; herramientas de build fijadas por SHA256 y compilador con Authenticode; actions por SHA con permisos mínimos. La corrección de vulnerabilidades transitivas se hace actualizando paquetes de prueba, no suprimiendo la auditoría. Publicar archivos no activa reglas de GitHub ni Actions: el propietario debe configurarlas. El push inicial se realizó al publicar 1.1.0.
25. **Renombre integral y carpeta de datos nueva** (2026-10-28, 1.1.0): eliminar todo identificador del nombre anterior en solución, proyectos, carpetas, namespaces, XAML, scripts, CI, documentación, variable de entorno y log. La carpeta de datos pasa a `%LOCALAPPDATA%\Viciotek`; no se copia, mueve ni borra la carpeta personal anterior, y la migración queda documentada como paso manual del propietario. Se conserva el `AppId` del instalador para actualizar sobre 1.0.x sin perder archivos. El icono oficial se regenera desde el PNG aportado y se aplica a ejecutable, ventana e instalador. Se publica `main` en GitHub; rulesets, reporte privado, Releases y firma siguen siendo configuración manual.
